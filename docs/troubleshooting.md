﻿# 常见问题与排查

## 先看这几条

```bat
winst --version                  :: 版本是否最新
winst config list                :: 实际生效的配置
winst info <id>                  :: 这个软件各源版本、安装状态、缓存状态
winst repair --dry-run           :: 台账是否与实际不一致（不写盘）
winst --verbose list             :: 详细日志
```

`--dry-run` 不下载、不安装、不写台账或缓存索引；软件源查询仍可能联网，需要完全离线时同时加 `--offline`。winst 自身安装的预览会明确拒绝执行。

## 安装与更新

### 「已安装 x，但软件源里没有可用版本」

条目声明了 `source.versionFrom: "package"`（版本要等包下载后才知道），或源侧确实没给出可比较的版本。加 `--force` 强制安装 / 更新。

### 「已安装 x，软件源是 y，需要 --force 才能降级」

源侧版本比本机低。确认要继续降级就加 `--force`。

### 版本相同但又要装一次

同版本默认跳过、不动任何文件。要强制重装：`winst install <id> --force`。

### 下载很慢 / 失败

```bat
winst install <id> --proxy http://127.0.0.1:7890
winst config set proxyMode always      :: 一直走代理
winst config set proxyMode download-direct  :: 下载直连优先，其它请求走代理
winst config set proxy http://127.0.0.1:7890
```

- 代理只影响 winst 自己的请求；软件包下载由 FluxDown 执行，`--proxy` 会传给下载器
- `proxyMode` 可选 `auto` / `always` / `off` / `download-direct`，写错会被拒绝（不会悄悄退回默认值）
- 下次下载前会清理本目标的 `.fdownloading` 与 `名称 (N).zip` 残留；失败后可重试
- 部分站点对自动化请求返回 403，清单里对应条目会用 `fetchWith: "browser"`（系统自带 Edge 无头抓取）

### 解压失败

解压首选 `7-Zip-CLI`，它不可用时依次退到系统自带 `tar.exe` 与 `Expand-Archive`（仅 zip），**不会**去用目标机上安装的完整版 7-Zip：

```bat
winst install 7-Zip-CLI --force
```

7-Zip 自解压包（`7z<版本>-x64.exe`）先按原样交给 `7-Zip-CLI` 或系统 `tar.exe`（两者都能直接打开它）。只有安装 `7-Zip-CLI` 本身、且两者都打不开时，才按 PE 覆盖区起点定位内嵌 7z 载荷再解一次——不扫描文件内容，也不运行这个安装包。原因是老系统自带的 `tar.exe` 是 libarchive 3.6 及以前，只在 `0x27000`～`0x60000` 之间扫 7z 签名，而新版 7-Zip 的载荷起点已经前移到这个窗口之下，所以同一份包在新系统能解、在 Windows 10 21H2 这类老系统上会报「无法识别的归档格式」——这不是包损坏，是系统工具太旧。

失败时 `--verbose` 会带出 7z 的原始错误，可据此判断是包损坏还是格式不支持。

### 「请以管理员身份运行 winst」

winst 启动时自动申请管理员权限（`RunAs`），因为安装软件要写系统级环境变量、静默运行 msi / exe 安装程序、读写 HKLM 卸载记录。UAC 被取消时会明确报错并退出，不会偷偷降级成「无权限继续跑」。

- 只想查看信息、不想弹 UAC：设 `WINST_NO_ELEVATE=1` 后运行（只读查询不需要管理员）
- `-v` / `--version` / `version`、`-h` / `--help` / `-?` / `help` / `?` 不提权：这些会被别的 winst 进程频繁调用做版本检测，每次弹 UAC 会让自更新卡死
- 把 `installRoot` 指到用户目录下（默认位置）时，环境变量落在用户作用域，本来也不需要管理员

### 目标程序正在运行，无法继续

```bat
winst install <id> --kill      :: 自动结束
winst uninstall <id> --kill
```

不自动结束时，交互模式会列出进程并提供 `k`（结束）/ `c`（手动关闭后继续）选项。

## 卸载

### 「没有安装记录，无法卸载」

`download` 类型条目从不写台账。要清理它的缓存：`winst clean <id>`。

### 「非 winst 安装，只移除登记」

`managed: "external"` 的条目默认只删台账记录，不动文件；清单或台账里已有卸载定义的除外。要对默认只登记的条目实际执行卸载，加 `--force`。

### 卸载后程序文件还在

卸载程序可能已执行成功但需要重启，或卸载器没有清干净；安装目录残留默认会保留并列出路径。先重启再检查，仍残留时手动删除安装目录。若只是卸载命令失败且软件已手动移除，可加 `--force` 只移除登记；不要指望这个开关清理已经留下的文件。

### 列表里为什么显示「还并存旧版本」

本机同时装着同一个软件的多个版本时会这样（典型：`.NET Desktop Runtime` 升级后旧构建还留在 `C:\Program Files\dotnet\shared\Microsoft.WindowsDesktop.App\` 下）。列表只展示最新版本，旧版本用这一行标出来；进详情选 `o)` 可以逐个确认后清掉。

- 只收「同一产品」的低版本：VC++ 2019 与 2022 这类可以并存的不同产品不会被当成旧版本
- 清理要交互确认；输入被重定向时整段跳过，不静默卸载
- 同一版本常有两层记录（外层引导包 + 内层 MSI）。外层卸载器在 `%ProgramData%\Package Cache` 下，被磁盘清理删掉后这条记录就成了孤儿——winst 会改用内层 MSI（`MsiExec.exe /X{GUID}`）卸掉，并在成功后清掉那条孤儿记录；只有全部记录都不可用才报失败
- 显示「找不到这个版本的卸载入口」说明系统安装记录里也没有对应条目，只能到「设置 → 应用」手动卸载；若那里也没有，就只剩遗留目录
- 想让登记立刻反映现状：详情页 `r)` 重新检测版本，或跑一次 `winst repair`

## 台账与缓存

### 安装记录看起来不对

```bat
winst repair --dry-run     :: 先看会改什么，不写台账或缓存索引
winst repair               :: 校对 state.json，必要时重建缓存索引
```

`repair` 扫描安装根目录、注册表卸载项、Appx 记录重建台账，并校对 `<pkgDir>\winst.json`。它不修改软件文件、环境变量或快捷方式；缓存索引损坏时先备份为 `winst.json.bak`，再按目录内实际文件重建。

### `state.json` 损坏

winst 会自动把它备份为 `state.json.bak-<时间戳>` 并重建，随后 `winst repair` 可把已装软件扫回来。

### 改了 `installRoot` 之后列表空了

台账跟着安装位置走：新位置没有 `state.json`，进入「已装软件」会自动扫描一次，或手动 `winst repair`。

### 缓存列表与实际文件不一致

`winst list --cached` 只列出 `<pkgDir>\<id>` 下实际含文件的目录；空目录不算有缓存。索引指向已删除目录的条目会被剔除，索引缺失或损坏时可运行 `winst repair` 重建。目标包文件确实缺失或校验失败时需要重新下载。

### NAS / U 盘路径

`pkgDir` 可以直接指向 UNC 路径：

```bat
winst config set pkgDir \\NAS\winst\apps
```

- 网络共享**只支持 UNC 路径**，不支持映射盘符（`Z:\...`）：映射只在当前登录会话可见，winst 以管理员身份运行时往往访问不到，`config set` 会直接拒绝这类输入。
- 共享需要账号密码时，`config set` 不支持带凭据的写法（它需要交互认证）。请到「设置 → 安装包位置」：先输入 UNC 路径，再按提示单独输入账号与密码（密码不回显，两者都可直接回车跳过）。那里会调用系统凭据管理器（cmdkey）先认证、成功后才保存，账号密码不写进 `config.json`。
- 多台机器共用时，安装包、软件源列表、清单缓存都在同一台机器上，换机下载后可直接刷新这些文件
- 配置文件通过临时文件 + 替换的方式写入，避免写一半损坏；只有单个用户可能访问的问题，多机同时写会互相覆盖
- 目标目录挂在 NAS 时只影响新的下载，已安装的软件不受影响

## 软件源

### 「软件源里没有这个软件」

```bat
winst manifest list
winst manifest update --all
winst search <关键字>
```

本地清单也要参与：把 `manifest.json` 放在脚本同目录、或 `<pkgDir>\manifests\*.json`，自动识别为 `local` 源。

### 安装时只看到「失败 1」，没有原因

失败提示现在会逐条给出原因：

- 菜单「安装软件」：原因紧跟汇总行，形如 `失败原因: Eclipse Temurin JDK 21（jdk21）: …`
- `winst install`：同上，形如 `失败原因: jdk21: …`
- 原因来自 `Invoke-WinstInstallTarget`；选不到可用来源时，它会把**每个软件源**各自的失败原因都列出来（哪个源没发布版本、哪个源字段写错、哪个源网络不通），据此去修对应的源
- 加 `--verbose` 重试可以看到更详细的过程（HTTP 请求、来源解析、文件匹配）

### 源刷新失败

- `--offline` 下不刷新，只用已有缓存与本机清单；`manifest update --offline` 会直接报参数错误
- 单个源失败不影响其它源，刷新汇总会给出成功 / 失败数；网络失败返回 `2`，其它刷新失败返回 `1`
- 刷新时打印的源名来自 `<pkgDir>\manifests\sources.json`。列表里若还留着一条早已不用的来源，用 `winst manifest remove <名称>` 删除，它的清单缓存与 sidecar 会一并清理
- 条目级失败（地址 404、页面结构变了、字段缺失）不会让其它条目失败。`manifest update` 逐条显示「有误」并在末尾列原因；若该条目有上次成功结果，会保留旧结果并注明本次失败原因
- `manifest list` 只显示各来源与清单概况；要看条目错误，执行 `winst manifest update <名称>`
- 条目报「HTTP 404 地址不存在」但同一条地址用浏览器能下：多半是 CDN 的人机校验。带 `Cf-Mitigated: challenge` 的响应按「未能确认」处理（备注提示），不判失败——JetBrains 的中国 CDN 对 .NET / PowerShell 客户端一律回 404；此时仍报 404，说明地址真的写错了

### 内置源 `dsx42/winst-manifest` 改不了 / 删不掉

设计如此：它是内置源，缺失会被补回、地址被改会被纠正、不能删除。要自定义某个软件，在本地清单里写同 id 的条目即可，两个源并存、安装时可选。

## github 源

### 「最新版本 x 里还没有符合 … 的安装包」

上游刚建好 release、资产还在分批上传。winst 会自动退回更早的发布（最多查最近 5 个），用第一个确实含有该文件的发布，并在结果里写明「最新发布 x 里还没有这个文件，已改用更早的发布 y」。

候选按 **`releases` 列表页 + 版本号排序** 得出：列表页是发布信息的唯一来源（tag / 标题 / 正文 / `Pre-release` 标记都在上面），不用 `releases.atom`——它只有最近约 10 条，adoptium 的 temurin21/temurin25 feed 里甚至是 2023 年的 nightly beta，近期正式版一条都没有；而且两者顺序都不代表版本高低（`21.0.9+10` 会排在 `21.0.13+9` 前面）。

- 想让它等最新发布传完、不要装旧版：清单里写 `"latestOnly": true`
- 报这个错说明**最近几个发布都没有**你要的文件，先核对 `files[]` 的通配（如 `7z*-x64.exe`）是否和上游命名一致
- `files[].url` 写了**完整地址模板**时不会触发回退：那种 404 通常意味着模板写错（tag 前缀、路径、文件名），静默装旧版只会掩盖问题
- `25+36` 这类 JEP 223 写法按 `25.0.0` 参与排序（`+build` 不参与比较）

## 页面型来源（page / listing / json）

### 「全部候选都不可用」

`listing` 源会从高到低探测候选地址（上限 8 个）。列表页里混入的噪声数字占满名额时就会这样。改用能直接给出真实版本的来源：`page`（带版本号的下载直链）或 `json` 接口。

### 「页面提取不到下载链接」

站点改版。排查顺序：

1. `--verbose` 看候选链接列表
2. 调整清单里 `link` 的 `class` / `id` / `text` / `href`
3. 地址由点击生成时改用 `source.click` + `fetchWith: "browser"`
4. 命中的是中转页时改用 `source.thenLink`（再抓一层）或 `thenClick`（浏览器里再点一次）

### 「浏览器没有返回页面内容」

系统浏览器（Edge）无头抓取拿不到 DOM，`fetchWith: "browser"` 的条目因此解析失败。

抓页面有两条通道，正常情况下不必关心走的是哪条：`--dump-dom`（子进程 stdout）与 DevTools 协议（CDP，WebSocket）。winst 会按进程是否提权自动选路 —— **提权进程里只能用 CDP**。

- 提权进程里 `--dump-dom` 注定空白：Edge 从提权进程启动时会把自己降权重启（Chromium 的 de-elevation），重定向给 winst 的 stdout / stderr 一个字都收不到，而 profile 是正常建好的（20 MB 上下）、也没有崩溃转储，光看现象很容易误判成页面打不开。winst 安装与刷新都跑在提权进程里，所以这是常态而非偶发
- 非提权进程先走 `--dump-dom`，拿不到内容再用 CDP 兜一次
- `--dump-dom` 这条还会先清掉占着 profile 的残留浏览器：profile 被占用时它只把命令行转交给在跑的实例、自己立刻退出，stdout 同样为空。清理后仍拿不到内容时会删掉 profile、换新目录再试一轮
- 两条都失败时报错会同时给出两边的原因（`--dump-dom` 那条还会附上浏览器 stderr 尾部，如 `Multiple targets are not supported in headless mode`），据此区分「启动参数/实例冲突」与「页面本身打不开」
- 站点要求登录、或下载地址藏在强 JS 校验之后时两条路都走不通，改用 `listing` / `json` 源

### 下载地址过期（403 / 404）

签名地址通常 1 小时左右失效。winst 在下载失败时会自动重新解析来源取新地址并重试一次。

## 快捷方式与环境变量

### 快捷方式双击打不开 `.ps1`

`.lnk` 指向 `.ps1` 时双击只会打开编辑器。winst 创建快捷方式时会在脚本旁生成同名 `.cmd` 启动器，并让快捷方式指向它；启动器生成失败时会明确提示并跳过快捷方式。`winst` 自身也是 `winst.ps1` + `winst.cmd`。

### 快捷方式指向旧位置 / 打不开

换了软件安装位置、或手工改过快捷方式以后，桌面 / 开始菜单里的 `.lnk` 可能还指着已经不存在的程序。安装 / 更新时 winst 会按「目标程序 + 起始位置」逐项校验：指向不对就覆盖修正，指向正确则不动文件。「只更新文件」模式下**只修正已存在的、不新建**。要一次性修好全部已装软件的快捷方式，重装对应软件即可。

### 换了软件安装位置，已装的软件去哪了

改「设置 → 软件安装位置」时，winst 会列出旧位置下已有的软件目录。已装软件留在旧位置继续可用，换位置只对此后的安装生效；安装记录跟着安装位置存放，新位置暂时是空的，进入「已装软件」时会自动扫描登记。要在新位置使用某个软件，把它在新位置重新安装即可。

### PATH 里出现重复项

winst 写入前会按原始文本比对（不区分大小写，已有项忽略首尾空白和包围引号），已存在就不重复追加。它不会合并 `%VAR%` 与实际路径等价的不同写法，也不会清理既有重复项；重复项需手动处理。卸载只会回收台账登记为本次写入的 PATH 项，不会借此清掉原有重复项。

### 环境变量里写的是 `%JAVA_HOME%\bin` 而不是真实路径

正常。`%VAR%` 会原样写入（`REG_EXPAND_SZ`），这样切换 `JAVA_HOME` 时 PATH 会自动跟随。`{installDir}` 与 `{installRoot}` 则展开为本机实际路径。

### 卸载后环境变量没了

winst 只回收台账里登记为「它自己写入」的项。手动配置的同值项不会被登记，也就不会被删除；winst 写入的项会被移除。若另一份已装软件仍声明同名变量，卸载会恢复为那份软件需要的值；仍被其它软件使用的 PATH 项则保留。winst 不保存安装前的原始值，需要保留时请在卸载前手动记录。

### Windows Terminal 里变量显示未展开

`REG_EXPAND_SZ` 的 `%VAR%` 在 Windows Terminal 里存在已知不展开问题（microsoft/terminal#9741），不是 winst 的问题。需要固定值就直接写实际路径。

## 交互菜单

### 菜单里粘贴路径没反应

「安装软件」的关键字输入会识别盘符、`\` / `/` / `.\` / `..\`、含反斜杠的路径，以及以 `.exe` / `.cmd` / `.bat` / `.ps1` / `.lnk` / `.msi` 结尾的命令行，提示这不是软件名称并重新输入；不会把这些路径当关键字搜索。

### 中文乱码

- 脚本文件被改成了无 BOM 的 UTF-8（Windows PowerShell 5.1 会按 ANSI 读），重新保存为 UTF-8 with BOM
- 控制台代码页不对：`chcp 65001` 或 `chcp 936` 后再试
- `build.cmd` 必须是 GBK，被改成 UTF-8 后批处理里的注释与提示会乱码

## 退出码

| 码 | 含义 | 常见原因 |
|---|---|---|
| `0` | 成功 / 取消 / 菜单正常返回 | |
| `1` | 参数错误、找不到目标、内部错误、单进程锁被占用 | 命令拼错、id 不存在、清单非法、已有另一个 winst 在运行 |
| `2` | 网络失败 | 代理不通、目标站不可达 |
| `3` | 安装 / 卸载 / 校验失败 | 校验不匹配、解压失败、卸载命令非零退出 |
| `4` | `update --check` 发现可更新项 | 正常，不是错误 |

脚本化使用时区分 `0` 与 `4`：后者表示「有更新但没执行」。

## 已知限制

- 只支持 x64 Windows 10 / 11
- 只支持 Windows PowerShell 5.1（不保证 pwsh 7 下可用）
- 静态 HTML 解析不执行 JS；需要渲染或点击的站点可用 `fetchWith: "browser"` / `click`，但不处理登录与验证码
- 环境变量与 PATH 只覆盖「当前用户」与「本机全部用户」，快捷方式始终为当前用户创建
- 下载能力只有一档（FluxDown CLI），它不可用时没有 `Invoke-WebRequest` 兜底
- 解压首选 `7-Zip-CLI`，退路只有系统 `tar.exe` 与 `Expand-Archive`（仅 zip）
- 不记录环境变量 / PATH 的原始值：卸载时只按台账回收 winst 写过的项
- 单进程锁只协调同一数据目录下的本机进程；多机共用 `pkgDir` 时，并发写同一索引文件仍是「后完成者覆盖」
