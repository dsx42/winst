# 常见问题

先使用 `--verbose` 获取具体失败原因。命令、退出码和预览边界统一见 [CLI](cli.md)，配置及文件位置见 [数据文件](data-files.md)，第三方软件源字段见 [清单规范](manifest.md)。

## 启动与权限

| 现象 | 排查和处理 |
|---|---|
| 提示已有 winst 在运行 | 检查提示的 PID；同一 WINST_HOME 只运行一个写操作，不删除锁文件强行并发 |
| 管理员启动被拒绝 | 确认 UAC 和系统策略；只读排障可设置 WINST_NO_ELEVATE=1，版本/帮助自动不提权 |
| 中文乱码 | PowerShell 源文件使用 UTF-8 BOM，build.cmd/winst.cmd 使用 GBK；按 [开发文档](development.md) 检查格式 |
| 菜单里粘贴路径被拒绝 | 软件搜索框需要软件名或 id；目录在设置中填写，本地 winst 包使用 install winst --from |

## 下载与网络

- 软件包下载使用 FluxDown-CLI。提示引擎不可用时，先检查软件源与引擎安装结果；不要把元数据 GET 成功等同于引擎下载成功。
- 代理不通时检查 `winst config get proxy` 与 `proxyMode`。`winst config reset proxy` 清除 winst 的显式代理；默认 HTTP 请求仍继承系统代理/PAC，off 不强制绕过系统代理。
- 带签名的下载地址可能过期；下载失败后会重新解析并重试一次，持续失败时刷新对应来源并查看 verbose 输出。
- 404/410 通常表示地址不存在；响应明确带 `Cf-Mitigated: challenge` 时表示站点挑战，不能据此确认文件缺失。浏览器能下载不代表所有自动化通道都能通过挑战。
- 校验失败时先确认包文件和对应摘要属于同一版本；不要手工把不匹配的摘要写入索引。缓存复用和摘要信任边界见 [清单规范](manifest.md)。

## 解压与浏览器

| 现象 | 排查和处理 |
|---|---|
| 无法解压 | 查看各解压工具的具体失败原因；确认 7-Zip-CLI 可用、文件完整及格式受支持 |
| 包内路径不存在 | 核对 stripTopDir/extractFiles/installerExe 与真实归档布局，不通过猜路径跳过必需文件 |
| 页面提取不到链接 | 用 verbose 查看候选，按清单规范调整 link、click、thenLink 或 JSON 来源 |
| 浏览器没有返回页面 | 确认系统 Edge 可运行、网络和代理正确；查看报错中的 CDP 或输出捕获原因 |
| 浏览器被占用或无头实例异常 | 关闭本次异常实例后重试；不要把个人浏览器配置当作 winst 临时 profile |

浏览器抓取不处理登录和验证码。条目需要这些步骤时，应使用能公开访问的合法下载来源。

## 软件源与清单

```bat
winst manifest list
winst manifest update <名称>
winst search <关键字>
winst info <id> --force
```

- 新的本地清单也需要生成解析结果；可放在脚本根 manifest.json、脚本 manifests/*.json 或 pkgDir/manifests/*.json。发现规则见 [清单规范](manifest.md)。
- 搜索没有命中时，联网模式会按正文补找并解析；离线和预览不会执行这一步。仍无结果时单独刷新来源查看具体条目错误。
- 来源无法持久化时，本会话采用已解析结果；修复只读共享/权限问题后重新启动，避免把会话结果当成已写入磁盘。
- GitHub 最新发布暂缺资产时，可按清单定义回退到更早且通道匹配的发布；需要只接受选定发布时使用 latestOnly。具体规则统一见清单规范。
- 内置源会自动恢复到首位和固定地址，不能删除；自定义定义放独立来源，安装时选择实际需要的来源。

## 台账与缓存

```bat
winst repair --dry-run
winst repair
winst list --cached
```

- 安装记录不完整时先预览 repair，再执行校对。扫描发现的软件不表示其环境变量、PATH 或快捷方式由 winst 创建，不能凭扫描推断回收所有权。
- 台账损坏时，先安全备份再恢复；遇到备份失败或不支持的结构时先处理文件，不用空台账强行覆盖。
- 更换 installRoot 后台账位置也改变；旧软件留在原目录，新位置需要扫描或重新安装。
- 缓存列表以实际目录中的文件为基础；不存在的目录会从索引移除，缺包需在联网环境补齐。
- 旧包清理或文件复制拒绝 junction/符号链接时，确认实际目标；不要为绕过保护而把用户资料目录设成软件目录。

## NAS 与离线套件

- pkgDir 支持 UNC 网络共享；installRoot 只允许本地路径。映射盘符可能不在提权会话可见，应填写真实 UNC。
- 共享需要凭据时使用「设置 → 安装包位置」交互输入，密码不写配置；凭据保存失败与共享已有连接可达是两件事。
- 多机共享索引通过包目录下的 `winst.json.lock` 串行读改写；等待超时应稍后重试，不删除锁文件强行写入。安装包文件及软件源刷新不在此锁范围内，避免多机同时修改同一个包或刷新同一个源。
- 套件缺包时，联网机器可补下载后重新打包；只下载后才能确认版本的合法条目会先取包确认，不应当作无来源。
- 同主版本的附件也可能更新；重新打包会逐文件确认内容，索引只在相应复制成功后更新。

## 卸载与系统设置

- type=download 没有安装记录，删除下载包用 `winst clean <id>`。
- external 条目有实际卸载定义时会卸载程序；没有定义才只移除登记。以确认页面显示的真实动作和来源为准。
- 卸载器要求重启时先重启；残留目录只有在安全检查通过且用户确认后才清理。
- 原安装变量的恢复依赖台账中的应用记录。旧记录缺少所有权/原值证据时会保留并提示，不推断它可以被删除。
- PATH 按台账回收实际写入项；不清理用户既有重复项，也不把 `%VAR%` 和已展开路径擅自合并。
- 「只更新文件」保留 env/PATH，修正已有快捷方式但不新建；完整更新与首次安装的行为见 [安装流程](install-flows.md)。
