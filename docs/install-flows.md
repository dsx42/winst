# 安装、更新、卸载与修复

## 版本检测

`detect.method` 决定如何识别本机版本，`detect.versionRewrite` 只规范化检测值；源侧版本由 `source.versionRewrite` 单独处理。

| method | 版本来源 |
|---|---|
| `registry` | 按 `detect.name` 匹配 HKLM（含 WOW6432Node）/ HKCU 的 Uninstall 项，读取 DisplayVersion，并由系统安装记录解析实际安装目录 |
| `fileVersion` | 读取 `pathGlob` 命中文件的文件版本；文件版本字符串与数值体不一致时按实现规则取舍 |
| `markerFile` | 读取 `pathGlob` 命中的标记文件内容 |
| `jsonFile` | 读取 `pathGlob` 命中的 JSON 文件里 `jsonKey` 指定的值，支持点分嵌套 |
| `appx` | 按 `detect.name` 匹配 `Get-AppxPackage` 结果，取版本最高的那个包，读取版本与 InstallLocation |
| `cliVersion` | 执行主程序或 `detect.exe` 加 `versionArgs`，先识别 stdout，未命中再识别 stderr |
| `none` | 不执行本机检测；新记录没有其它版本来源时可记为 `unknown` |

**同一软件装过多个版本**时（升级后旧版本没被清掉，如 .NET Desktop Runtime 保留旧的构建目录），`registry` / `fileVersion` / `markerFile` / `jsonFile` 会读出**全部**命中版本：展示与本机版本取其中最高的那个，其余记进台账的 `oldVersions`，在「已装软件」列表标注「还并存旧版本 x」，详情页给 `o) 清理旧版本` 逐个确认后移除。版本比较一律走 `Compare-WinstVersion`，不按字符串排序。`registry` 命中同一安装器的外层引导包与内层 MSI 时只用外层引导包的 DisplayVersion（内层 MSI 的 80.x 是内部编号）；`appx` 只取最高版本，不把运行时家族的其它包当作旧版本。

文件类检测只知道「还有这个版本的文件」，因此旧版本的移除入口按版本号反查系统安装记录（显示名里带该版本号的那条）得到；查不到时如实提示去「设置 → 应用」手动卸载，不猜测。

文件类检测用 `versionKind` / `versionBetween` 识别文本。`cliVersion` 默认参数为 `-v`，超时 10 秒，在隐藏进程中运行并重定向输出；`.ps1` 由 PowerShell 启动，`.jar` 由 java 启动。

安装完成后的检测异常不推翻已完成的文件落位：异常检测给出一行提示，`--verbose` 显示更多细节；台账版本依次取实测版本、本次目标版本、原台账中的有效版本，不用 `unknown` 或空值覆盖已知版本。安装前能发现软件但不能识别版本时，按下表决定是否继续。

## 安装决策与参数

| 本机与目标版本的关系 | 默认行为 |
|---|---|
| 未检测到 | 安装 |
| 相同，配套文件也无变化 | 跳过；已有台账保持不变 |
| 相同，只有配套文件需要更新 | 有台账且安装目录可用时走「仅配套文件更新」 |
| 本机低于目标 | 直接更新，不需要 `--force` |
| 本机高于目标 | 跳过并提示；`--force` 才允许降级或重装 |
| 已发现软件但版本无法识别，或源侧没有版本 | `install` 跳过并提示；`--force` 才继续 |

`source.versionFrom: "package"` 的目标版本取自主包。解析结果为 `remoteFresh: "unchanged"` 时复用缓存包及其版本；结果为 `changed` 或无法确认时，先重新取包再套用上述决策，不能拿缓存版本代表远端当前版本。`--dry-run` 不取包，只说明将先取包核对。

github 源在「最新发布里还没有所需文件」时会退回更早的发布（见 `docs\manifest.md` 的 github 源）：这时目标版本是那个**旧发布**的版本，不是最新 tag。解析结果会带上「最新发布 x 里还没有这个文件，已改用更早的发布 y」的说明；升级判断与 `--check` 都以这个实际采用的版本为准，因此不会把「装了旧发布」误报成「已是最新」。

同版本 installer 跳过时会按系统记录修正或清除占位安装目录。检测到同版本软件但尚无台账时，会补一条 `external` 登记；这不等于完全无写入。

常用参数：

- 全局：`--yes` / `-y` 跳过确认；`--dry-run` 的行为见 [CLI 预览边界](cli.md#预览边界)；`--offline` 禁止联网。全局开关可放在命令前后。
- `install`：`--force`、`--overwrite`、`--keep a,b`、`--kill`、`--files-only`、`--system-items`、`--source <名称>`。
- `install winst --from <路径>` 只用于本地自安装；其它安装类开关不适用，`download --from` 也不可用。
- `update`：支持 `--check`、`--download-only`、`--force`、`--files-only`、`--system-items`、`--source <名称>`、`<id>...` 或 `--all`。`--check` 与 `--download-only` 互斥；`--all` 不能与具体 id 或 `--source` 同用。
- `uninstall`：支持 `--force`、`--kill`、`--yes`。

`--files-only` 始终跳过环境变量与 PATH，首次安装也不补齐；但**已存在的快捷方式仍会校验**（指向不对就修正，见「安装流程 → 系统项」）。未指定时，`updateFilesOnly` 默认开启：已登记软件的更新或重装跳过环境变量与 PATH，首次安装只补缺失项；`--system-items` 优先于上述设置，按清单写入或覆盖。仅下载类型忽略安装类选项。

本体按已选来源解析依赖，依赖项选用最高可用版本的来源，不合并其它来源的依赖声明。依赖按传递闭包排序，只处理未安装或可更新的依赖，与本体统一确认一次；依赖失败会中止本体，清单中缺失的依赖只提示并跳过。仅下载类型不解析依赖。

## 安装流程

普通安装依次执行七个阶段。`download` 类型以及 `winst download`、`update --download-only` 的仅下载操作在取包、更新缓存索引后结束，不写安装台账。

### 1. 决策与取包

按文件级新鲜度决定复用或重取主包、配套包。普通软件包只由 FluxDown CLI 下载；需要下载而引擎缺失时先自动安装 `FluxDown-CLI`，引导失败则本次下载失败。

下载失败时可实时重新解析来源，仅在新地址指向同名、同版本文件时换地址重试一次。代理链失败后，可重试的网络错误还会用首选代理路径和单连接再试一次。下载完成后执行完整性校验；新下载文件校验失败会被删除。离线缺包或缓存无法通过当前校验规则时明确报错并保留现有文件。

### 2. 主包与配套文件落位

| 类型 | 行为 |
|---|---|
| `portable` | 解压到 `<installRoot>\<id>\`。`clean` 先清理目录并应用 `keep`，`overwrite` 直接覆盖；`--overwrite` 强制覆盖模式，`--keep` 只覆盖清理模式的保留规则。`stripTopDir` / `extractFiles` 控制解压布局 |
| `file` | 主包复制到 `<installRoot>\<id>\<下载文件名>` |
| `installer` | 运行安装器；声明 `installerExe` 时先解压主包并唯一定位包内安装程序。配套文件只缓存，不落位 |
| `download` | 只缓存，不解压、不安装、不写台账 |

非 installer 的配套文件按 `dest` 复制或解压到安装目录，并删除上次登记、本次已不需要的配套文件；含其它内容的旧目录保留并提示。落位集合写入 `appliedFiles`。`dest` 越界、经过重解析点、源文件缺失或落位失败都会报错。

「仅配套文件更新」只重取发生变化的配套包，再按清单落位配套文件和清理失效项；不重装主包，不执行复制改名、系统项或 `postInstall`，版本与系统项登记保持不变，只更新该条目的 `appliedFiles` 及写入时间。

### 3. 复制 / 改名

`postInstallCopy` 在安装目录内按 `from`（支持 `*`）复制，`move: true` 时移动到 `to`。来源不存在、命中多个、路径越界或经过重解析点都会报错。

### 4. 系统项

按 `env`、`addToPath`、`shortcuts` 落地：

- 安装目录在 `%USERPROFILE%` 下时使用用户作用域，否则使用全局作用域。快捷方式始终为用户级。
- `%VAR%` 原样写入，`{installDir}` / `{installRoot}` 按实际路径展开；先写 `env`，再处理 PATH。
- 只登记实际写入的 `appliedEnv` / `appliedPath` / `appliedShortcuts`。保留的已有变量不接管，同值项不重复写入。
- 快捷方式按「目标程序 + 起始位置」逐项校验：不存在就按清单创建；已存在且指向正确则保留（不重写文件）；已存在但指向不对（安装位置换过、旧版本残留、被手工改过）则覆盖修正。`--files-only` 或 `updateFilesOnly` 下**只修正已存在的、不新建**——用户删掉的快捷方式不该在更新时又冒出来，但留下的旧快捷方式必须跟着改到新位置。
- 系统项按当前更新方式处理，规则见「安装决策与参数」。快捷方式创建 / 修正失败只提示，不把未处理的快捷方式登记为已应用。

### 5. 安装后命令

`postInstall` 逐条执行 `exe` + `args`，支持安装目录内相对路径、绝对路径、占位符和 `%VAR%`。`timeoutSec` 默认 600 秒，超时结束进程树；`requireAdmin: true` 且当前未提权时不启动。退出码不是 `0` / `1641` / `3010`（后两者表示需要重启）、程序不存在、超时或参数含非法控制字符均判为失败；读不到退出码时也返回失败，要求核实执行结果。

### 6. 安装后检测

按 `detect` 重新识别版本，规则见「版本检测」。installer 还会回读系统安装记录以确定实际安装目录：短时间内多次探测，读不到时保留原有效目录，无法确认的占位目录可留空。

### 7. 写台账

写入版本、类型、安装目录、来源、`managed`、系统项登记、配套文件和卸载快照。已有系统项登记与本次结果合并；条目级写入会先重读最新台账，只覆盖当前 id，保留 `installedAt` 并刷新 `updatedAt`，避免覆盖流程中途自动写入的引擎或 winst 记录。

`pruneOldPackages` 开启且本次确实下载过文件时，同 id 的旧包在下载成功后、安装落位前清理，离线时不清理。它不是安装成功后的回滚或收尾保障。

安装过程没有事务回滚。下载、解压、复制失败时通常尚未写安装台账；系统项部分写入后发生异常，或 `postInstall` 命令失败时，会把已经成功落地的系统项登记进台账再报错（卸载仍能回收它们）。已经发生的目录清理、文件覆盖和系统项修改可能保留；台账写入失败时文件也已经落位，错误会明确区分这种情况。

## 安装版（installer）

1. UNC 主包先尝试复制到 `%TEMP%`；需要时先解出 `installerExe`。
2. `.msi` 通过 `msiexec.exe /i` 安装，并传 `TARGETDIR`、`/qn` 和 `installArgs`；其它安装程序直接运行。参数支持 `{installDir}` / `{installRoot}`。
3. 退出码 `0`、`1641`、`3010` 视为成功，后两者提示需要重启；其它非零码失败。读不到退出码时提示并继续。
4. `.msix` / `.msixbundle` / `.appx` / `.appxbundle` 使用 `Add-AppxPackage`，不复制到安装目录，也不使用 `installArgs`。
5. 安装后使注册表和 Appx 快照失效，再解析实际安装目录。声明 Appx 卸载的条目会尝试清理低于本次版本的残留应用包，清理失败不阻断安装。
6. 执行后续阶段并写台账。installer 的 `--force` 只放行重装或降级，不先执行卸载。

## 缓存与新鲜度

主包和每个配套包独立判定：

1. 文件不存在，或地址、展开后的文件名与缓存索引不一致 → 重取。
2. 声明固定摘要或外部校验文件 → 校验；不一致且可联网时删除后重取，一致则复用并补记实测摘要。
3. 未声明摘要时按 `refresh`：`ifMissing` 直接使用；`always` 每次重取；`ttl` 按 `lastCheckedAt` 与 `maxAgeHours` 判断；`auto` / `check` 用 HEAD 的 ETag、Last-Modified 和长度确认。
4. `auto` 无法取得验证器时退到 TTL；`check` 提示无法确认后重取。验证器请求失败本身不否定缓存。配套文件解析出独立版本且版本未变时可复用。

元数据、校验文件和 HEAD 请求走 `Invoke-WebRequest`；普通包下载走 FluxDown，代理由 `--proxy` 传入。`proxyMode` 决定代理口径：

| 取值 | 元数据 / HEAD 请求 | 软件包 / 引擎包下载 |
|---|---|---|
| `auto`（默认） | 先直连，失败再试代理 | 先直连，失败再试代理 |
| `always` | 只用代理 | 只用代理 |
| `off` | 只直连 | 只直连 |
| `download-direct` | 只用代理 | 先直连，失败再试代理 |

`download-direct` 用于「网页 / API 必须借代理才打得开，但大文件本身直连很快」的环境。`--offline` 不发起网络请求，只使用已有的解析结果（sidecar）与现有缓存：软件源要先刷新过一次才有解析结果，本地清单同样如此（它的正文在本地，但解析锁 `local.meta.json` 要刷新才生成）。

## 更新

`winst update` 未指定 id 或指定 `--all` 时遍历台账；指定 id 时只处理已安装项。它按 `manifestTTLHours` 刷新目标软件的定义和版本，再复用安装流程：

- `--check` 只报告、不重新取包；存在可更新项返回 4，没有则返回 0。`versionFrom: package` 条目按缓存包版本和 `remoteFresh` 判定：远端无新包且缓存包版本与本机一致时为最新，无法确认远端是否有新包时列为可更新，实际执行时再取包核对。
- 默认优先安装来源 `manifestOrigin`；该来源没有更新而其它来源有更新时，切换到有更新的来源并提示。`--source` 只对指定 id 生效。
- 版本相同且只有配套文件变化时走窄更新；本机更新时不自动降级。`--force` 可强制重装或降级。
- 普通条目在本机版本未知或源侧版本缺失但有可用定义时，执行更新会按定义继续；`versionFrom: package` 条目仍先取包核对，不强制重装。
- `external` 的 portable / file 只报告、不覆盖；external installer 可更新，成功后转为 winst 管理。
- `--download-only` 只刷新缓存，不安装；未安装软件应使用 `winst download <id>`。
- 菜单「检查更新」默认强制刷新清单本体；`pkgDir` 是 UNC 共享时逐条看 `resolvedAt`：仍在 `manifestTTLHours` 内的已装软件沿用共享解析锁，只有过期条目才重新解析（多台机器共用同一安装包位置时不必每台都重刷）；这些条目全部有效时整源跳过，清单本体也不再重新下载。

每条更新后重读台账。批量操作继续处理后续条目，结尾汇总；网络失败返回 2，执行失败返回 3，指定的 id 全部未安装返回 1。

## 卸载

卸载目标由台账卸载快照、当前已加载的软件源定义和台账系统项登记合并，相同动作去重；方式冲突以台账快照为准。软件源已删除条目时仍可使用快照，不为卸载额外刷新软件源。

1. 展示删除范围与依赖它的软件；依赖只提示，不拦截。`--dry-run` 在确认处结束，不执行任何修改。
2. 检测安装目录及 `processes` 声明的进程。交互中可选择结束、等待手动关闭或取消；非交互模式需要 `--kill` 才自动结束。
3. 在删除本体前执行台账与当前定义合并后的 `uninstall.commands`。失败即中止，目录与台账均保留；`--force` 跳过这些命令。
4. 按合并结果处理本体：
   - `portable-dir`：删除安装目录；winst 管理的目录必须位于 `installRoot` 下，越界时拒绝删除并提示。
   - `registry`：实时回读所有匹配的 Uninstall 项，exe 卸载器先于 MsiExec 执行；每条执行前再次确认记录仍存在。`1605` 视为当前记录已卸载，`3010` 记录需重启状态；两者都会继续处理剩余记录。
   - `appx`：按名称规则调用 `Remove-AppxPackage`。
   - `clean-cache`：只清缓存。
   - `record-only`：不动程序文件。
5. 环境变量 / PATH 只回收台账中的 `appliedEnv` / `appliedPath` 实际写入项，不因清单或卸载快照声明了移除项就接管用户已有设置；快捷方式按登记与卸载定义合并回收。仍被其它已装软件使用的 PATH 项保留；共享环境变量恢复为其它软件需要的值。
6. 删除台账条目前重新读取最新 `state.json`，只从最新状态移除当前 id 后落盘，避免抹掉卸载期间其它流程写入的记录。

`external` 没有可用卸载定义时使用 `record-only`；当前定义提供卸载方式时可实际卸载。registry / appx 卸载失败默认中止并保留台账，`--force` 或菜单中的明确确认可改为只移除记录。卸载器成功后的文件、目录或系统项残留只提示，通常仍继续移除台账；最终台账写入失败则明确报错。`--yes` 或输入重定向时不询问删除安装目录残留，默认保留。

按名称规则卸载会命中同名的**全部**记录，新旧两版会一起卸掉。只想清掉旧版本时用「已装软件」详情的 `o) 清理旧版本`：它按台账 `oldVersions` 里登记的卸载键运行对应的卸载程序（一次只卸一个版本），并且每条都要单独确认。确认页会提前说明「并存的旧版本会被一并移除」。

**同一版本常有多条记录**，卸载时不能只认一条：外层 burn 引导包的卸载命令指向 `%ProgramData%\Package Cache\{...}\xxx.exe`，磁盘清理掉缓存后这条记录还在、卸载器却已经不存在；内层 MSI 用 `MsiExec.exe /X{GUID}`，缓存在 `C:\Windows\Installer`，通常仍可用。因此：

- 登记 `oldVersions` 时就按「卸载器现在是否存在」挑记录（可用者优先，同可用性时非 MsiExec 优先）
- 执行时若登记的键报「卸载器文件不存在」，自动换同版本的其它记录再试（`Invoke-WinstOldVersionRemoval`），全部失败才报错并逐条列出原因
- 卸掉之后，同一版本里「卸载器已不存在」的孤儿记录会被清理（`Remove-WinstOrphanRegistryRecord`），否则它们会一直留在「设置 → 应用」里且点了也卸不掉

`uninstall winst` 删除 `<installRoot>\winst\`，不删除同级的 `state.json` 或安装包缓存。仅下载类型没有安装台账，应使用 `winst clean <id>`。

## 修复（repair）

`winst repair` 扫描本机并校对台账；菜单进入「已装软件」或「检查更新」时也会以 `-Quiet` 执行，菜单在 `--dry-run` 下跳过这段自动修复。

扫描范围：

1. `installRoot` 下全部直接子目录：按清单 id 匹配并用 `detect` 识别；没有清单条目的目录也按目录名登记，版本可为 `unknown`。
2. 注册表 Uninstall 项：匹配 installer 条目，新记录可使用系统记录中的安装位置。
3. 系统 Appx 记录：匹配 `detect.method: "appx"` 条目。

合并规则：

- 已有条目只在本次识别到有效版本时更正 `version`，其它字段保持原值；识别不到时保留原版本。已有条目的安装目录不会因本次扫描被改写。
- 每次扫描都会重写已有条目的 `oldVersions`：本次检测到同一产品的低版本就记下来，没检测到就清空（旧版本已经不在本机了）。
- 新条目按扫描结果和当前清单建立，包含来源、`managed`、推导的系统项登记与卸载快照。
- 仅大小写不同且指向同一目录的重复记录合并为清单 id。
- 安装目录缺失的已有条目只报告，不删除，也不动系统项；软件源中没有对应条目的已有记录同样保留。
- 同时校对 `pkgDir\winst.json`，缺失或损坏时按缓存文件重建，不删除软件包。
- 除必要的缓存索引写入外，只写 `state.json`，不修复程序文件或系统项。`--dry-run` 展示改动但不改这两类文件；损坏台账的安全备份仍由读取层执行。

`state.json` JSON 无法解析时，读取层先复制为 `state.json.bak-<时间戳>`；备份成功才以空台账继续，备份失败则拒绝后续台账写入。读取失败或 `schemaVersion` 高于当前支持版本时，repair 和 update 直接停止，避免用不完整状态覆盖台账。

## winst 自身的安装与更新

- **首次安装**：`install.ps1` 下载并解压 release 的 `winst.zip`，再调用 `winst install winst --from <zip>`。
- **本地安装**：`--from` 接受 zip 或已解压目录，不查软件源、不解析依赖、不联网。读取包内产品版本；目标已存在时，同版本跳过，降级要求 `--force`。
- **目录替换**：先将包放入临时目录，校验 `winst.ps1` 和 `Modules` 下的模块清单，并拒绝 `Modules` 中的重解析点。随后整棵清除目标 `Modules`，复制新树，再逐项核对相对路径、文件长度和 SHA256，防止旧模块残留或嵌套。`lists\` 与 `*.list` 保留；release 未提供的其它顶层项清理。
- **引导兜底**：仅首次安装且无法取得 release 包时，复制当前运行树的 `winst.ps1`、`Modules`、`winst.cmd` 和 `LICENSE`；缺少任一部分则明确失败；自动更新必须取得可验证的包，不能用当前脚本代替。
- **自动检查**：处理非 winst 的安装或更新目标前，每进程执行一次 `Confirm-WinstSelf`。缺失时尝试安装；已安装且清单版本更高时自动更新。`--dry-run` 跳过自动安装和更新，`--offline` 只跳过自动更新；自动安装或更新失败不阻断当前软件操作。
- **生效与台账**：当前进程继续使用已加载代码，下次启动使用新文件。取得清单包时台账记清单版本，引导兜底记当前产品版本；首次安装补齐系统项，更新只替换文件。台账按条目写入，保留 `installedAt`、刷新 `updatedAt`。

release 使用 `winst.ps1` + `winst.cmd` + `LICENSE` + `Modules\Winst\`；本地包也接受多模块布局，只要求 `Modules` 下存在模块清单。

## 下载与解压引擎

| 引擎 | 用途 | 安装目录 |
|---|---|---|
| `FluxDown-CLI` | 普通软件包的 HTTP / BitTorrent 下载 | `<installRoot>\FluxDown-CLI\` |
| `7-Zip-CLI` | 压缩包与安装器解包 | `<installRoot>\7-Zip-CLI\`，只保留 `7z.exe` 与 `7z.dll` |

引擎是内置源中的普通 portable 条目，首次引导和自动更新都会写台账与缓存索引。每次需要引擎时按进程级策略检查更新；任一侧版本未知、`--offline` 或 `--dry-run` 时不自动更新。已有引擎的更新失败可继续使用现有版本，但首次引导失败会阻断依赖它的下载；解压引擎不可用时还可使用系统后备。

解压顺序为 `7-Zip-CLI` → 系统 `tar.exe` → `Expand-Archive`（仅 zip），不借用目标机另行安装的完整版 7-Zip。安装 `7-Zip-CLI` 本身时，若三档都打不开官方自解压包，会按 PE 覆盖区起点切出内嵌 7z 载荷再解一次（不扫描内容、不运行安装包）；其它压缩包没有这一档，失败即报错。普通包下载没有 `Invoke-WebRequest` 后备；只有引擎引导包和 winst 自身包允许直接 HTTP 下载，以避免自举循环。

## 失败与退出码

- 批量安装、更新、卸载继续处理其它目标并输出汇总；单条依赖失败只中止其本体。
- **失败一定要有原因**：汇总行只报条数，逐条原因紧跟其后。原因已在该软件的处理过程里打印过就不再重复；没有打印过的由汇总补齐（`Invoke-WinstInstallTarget` 用 `FailureShown` 标记是否已就地说明，`Write-WinstInstallTargetResult` 在 `Error` 与 `Message` 都为空时给兜底文案）。
- 选不到可用来源时，错误里逐个列出**每个软件源**的失败原因（如「还没有发布任何版本」「源里没有 versionFrom 声明的字段」），而不是只给一句「软件源里没有可用的版本信息」——否则用户不知道该修哪个源。
- 下载和校验失败不写安装台账；校验失败的坏包删除。未完成下载及引擎改名残留会在后续下载前清理。
- 卸载命令失败发生在删除本体前，目录与台账保留；目录或系统项回收残留与台账写入失败是不同结果，按各自提示处理。
- 需要管理员权限而未提权时明确提示，不把权限问题静默当作成功。
- 退出码：`0` 成功或取消，`1` 参数、状态或内部错误，`2` 网络失败，`3` 安装、更新、卸载或校验失败，`4` 仅表示 `update --check` 找到可更新项。
